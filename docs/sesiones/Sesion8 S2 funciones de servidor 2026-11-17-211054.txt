  ## 1. El orden de las operaciones dentro de `apply_op`
  
  El PRD empieza por el `UPDATE`, pero la idempotencia pide otro orden:
  
  ```

   1. UPDATE last_seq+1 (bloquea)    1. rol y borrado   (member_role, deleted_at)
   2. INSERT diagram_ops             2. SELECT ... FOR UPDATE (bloquea)
      -> si op_id repetido: error    3. ¿existe (diagram_id, op_id)? -> devolver su seq
                                     4. ¿last_seq >= 5000?  -> rechazar

  ```

  ## Siguiente punto: el tope de 200 caracteres en las etiquetas
  
  Así está hoy:
  
  - `ops.js` solo valida el título. `addNode`, `updateNode`, `addEdge` y `updateEdge` aceptan etiquetas de cualquier longitud.

  maxlength=200 -->  label.length <= 200   -->   char_length(label) <= 200
